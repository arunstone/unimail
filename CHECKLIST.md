## Bayesian junk filter (BUILT, DEPLOYED & E2E-VERIFIED 2026-07-05 — TB-style adaptive spam classifier)
Per app user, learns from explicit training, then auto-classifies new inbox mail in EVERY connected account during sync.
- **Backend**: services/junk_service.py — Graham-style naive Bayes (top-20 most decisive tokens, Robinson smoothing (0.5+n·p)/(1+n), log-space combine); tokenizer = subject (s:) + body words + sender addr/domain (f:/d:), 300 tokens max/msg. Tables junk_tokens (user_id+token PK, spam/ham counts) + junk_stats (per-user trained-message counts) via create_all; manual prod ALTERs: users.junk_enabled BOOL DEFAULT TRUE, emails.spam_trained VARCHAR(4) ('spam'|'ham'|NULL — records the lesson so re-training reverses it).
- **Activation gate**: needs ≥3 spam AND ≥3 ham trained (MIN_TRAINED); threshold 0.90 (SPAM_THRESHOLD). Auto-caught mail is NOT self-trained (no feedback loop).
- **Endpoints**: POST /api/emails/{id}/spam | /not-spam (train + move + IMAP mirror); GET/PATCH /api/junk (stats + on/off). patch_email folder_role=spam/inbox also trains (drag-to-junk teaches, like TB).
- **Sync hook**: sync_service classifies new inbox mail the filter rules left alone; junk verdict rides the existing pending_moves → _push_filter_effects mirror to the server's Junk folder.
- **BUG FOUND+FIXED during E2E**: push_move with a detached UID (row just moved server-side by sync, imap_uid NULL) silently skipped the server move → "Not spam" right after an auto-catch stayed in server Junk and next sync flipped it back to spam. Fix: push_move now recovers the UID via IMAP `SEARCH HEADER Message-ID` in the row's folder.
- **Frontend**: EmailBodyView header gets 🚫 Spam / ✓ Not spam (label depends on folder_role, closes tab, toasts); Settings "Junk filter" section (On/Off pill, trained counts, Active/Learning status with how many more trainings needed).
- **E2E-verified live** (disposable junktest@example.com mailbox + app user, all cleaned up after): trained 3 spam + 3 ham → /api/junk active:true; fresh never-seen spam (megadeals.top) caught at score 1.000 on sync → app Spam folder + server Junk (doveadm); fresh legit mail stayed in inbox; Not spam → back to inbox locally AND server-side (after fix), ham count incremented; re-sync flips nothing back.
